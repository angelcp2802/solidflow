# Effective configuration numerical adapters

The separate [independent physical gate](ASSEMBLY_CONFIGURATIONS_VERIFICATION.md)
measures a fresh complete candidate context across the current inventory. A
detached numerical constraint cannot substitute for that native verification.

The [selected-scope adapter](ASSEMBLY_CONFIGURATIONS_SCOPE.md) now maps every
current family into an exact declaring scope's immediate-child numerical
bodies. Root projection remains available. Closed scope identity, all auxiliary
roles and the original full placement error are retained; configured solve and
atomic writeback still require a separate transaction.

The [capture/winding state layer](ASSEMBLY_CONFIGURATIONS_STATE.md) connects
complete named capture overrides to effective core mate declarations. These
adapters consume those selected values; they do not recapture them or publish
a variant solve/writeback transaction.

This layer converts authenticated effective-configuration observations into
**detached numerical constraints**. It builds on the separate
[configuration core](ASSEMBLY_CONFIGURATIONS_CORE.md),
[native observation context](ASSEMBLY_CONFIGURATIONS_NATIVE.md) and
[effective relation inventory](ASSEMBLY_CONFIGURATIONS_RELATIONS.md).
It does not solve a configuration, persist a variant or authorize an edit.

## Input and proof boundary

The input remains the complete `{ document, catalog, rootConfiguration,
generation }` context. The generation belongs to the caller and must advance
when its context changes, including a change away and back. A witness or
relation must be the exact object issued by that live configured snapshot.
Clones, declarations, evaluation DTOs, foreign snapshots and legacy witnesses
are not interchangeable with its private proofs.

`buildConfiguredAssemblyConstraint(snapshot, input, relation, id, options)`
dispatches the current relation family. The ordinary options are explicit
positive finite `lengthToleranceMm` and `angleToleranceRad`, defaulting to
`1e-6` mm and `1e-8` radians. Angular bands must be below pi; the hinge adapter
requires a band below pi/2 to distinguish axial and radial planes. Requested
bands are not widened. Numeric results are ordinary detached data; passing one
to a numerical solver does not authenticate a new native observation.

The mapping includes the current binary families, centered Width, the five
Symmetry entity purposes, profile center, LINE/circular path and four/six-role
hinges. It preserves declared alignment, branches, intervals, offsets,
mechanical captures and lifted angles; it does not recapture their values.
Advanced profile/path mapping has a dedicated adapter rather than an alias to
an ordinary plane, direction or infinite-line proof.

## Effective root-owner frames

`configuredAssemblyEndpointFrame` authenticates the witness, evaluates the
same effective declaration context and checks its terminal tuple,
configuration ancestry and availability. The rigid owner is the first full
occurrence-path segment, `path[0]`. The endpoint frame is composed from the
**effective occurrence poses below that owner**, in their declared order.
It does not invert a world placement or traverse the base definition's
unoverridden occurrences.

A witness on a top-level occurrence therefore has an identity endpoint frame.
A null role in a nested declaring scope retains that scope's descendant frame
and its original root owner. Only the document-root frame has `bodyId: null`
and identity placement. Selecting a reference scope never promotes its
children to independent root rigid owners. Hidden state does not itself remove
geometry; effective suppression makes the selected endpoint unavailable.

`configuredAssemblyEndpoint` additionally copies the actual local component,
point, plane, analytic support, direction or complete cylinder/sphere surface
into the existing numerical endpoint representation. It rejects advanced
profile/path witnesses, which require their dedicated mapping. A direction-only
witness stays a direction-only observation: the generic numerical shape does
not grant positional or complete-surface authority. Callers retain the original
family and proof purpose when selecting equations.

## Precision and purpose

Endpoint frames are kept local to avoid losing small descendant offsets under
large owner translations. This does not erase conditioning from the original
placement chain. Adapters retain the private `placementSum` and `depth` before
cancellation and combine them with the actual local support values and the
arithmetic required by the selected measurement.

Position, direction, radius and curve-coordinate budgets have different roles.
An explicit cylindrical axis used as a LINE does not acquire a radius
constraint or a radius precision gate. Surface purposes and an actual pitch
radius conversion do use radius information. Angular-only equations do not
become positional constraints merely because their native producer has a
location. Native topology tolerances are not converted into angular metrology.
These are numerical error policies for the declared native-reference model,
not calibrated physical accuracy or a formal interval certificate.

## Hinges and independent measurement

The hinge adapter preserves both axis roles and both axial-plane roles, with
an optional pair of material angular planes. Each corresponding axis/plane
pair must retain the same actual root rigid owner; different descendant frames
are allowed. Axial planes must be perpendicular to their corresponding axes
within the structural `1e-12` radian check. A radial plane is not substituted
for an axial plane. Unlimited hinges retain free roll; a limited hinge carries
its explicit `directed-about-axis` interval and both additional plane roles.

The builder uses the strict numerical hinge copier, including total positional
budgets that include the supplied support tolerance. Angular observability and
interval satisfaction remain evaluation duties.

`measureConfiguredAssemblyHinge` measures the authenticated native support
values independently of numerical residual rows or solver state. It evaluates
signed axis alignment, transverse axis separation and axial-plane offset. For
limits it uses the first selected axis as the signed guide and measures the
projected angular-plane phase with an error disk, an interval chart-cut guard
and explicit finite bands. Nominal agreement alone is insufficient when its
retained error consumes the remaining requested band.

This report is `supportOnly` and `verificationOnly`. It borrows the existing
snapshot, performs no fresh native query and does not certify a solved candidate
or an Apply operation. Singularity, unresolved projection or insufficient
precision must not be replaced with an invented phase or a looser band.

## Profile and material-path boundary

The dedicated advanced mapping retains complete circular profiles or explicit
rectangle boundary axes, rather than inferring roll from a circle seam or a
long rectangle side. Ordered profile-center offsets and rectangle orientation
remain explicit. See the [profile solver contract](ASSEMBLY_PROFILE_CENTER_SOLVER.md).

Material LINE and open circular paths retain their explicit material origin
and directed frame. Free LINE uses its explicitly declared underlying-line
semantics; circular Free keeps its declared `trim` or `support-circle` domain.
Fixed coordinates must be admitted against the actual current native extent,
without clamping. A fixed circular measurement requires current finite native
point/tangent evaluation (D1), retaining evaluation-specific arithmetic rather
than replacing it with the observation's center budget. Follow and optional UP
retain their actual component axes and separate guide owner.

Independent advanced measurement must use actual native values, physical
position/angle residuals, domain margins and retained finite errors. A Free
analytic support extension is not a fabricated finite native evaluation.
Near-axis or chart-cut ambiguity cannot be hidden by normalizing an undefined
projection. The [LINE contract](ASSEMBLY_LINE_PATH.md) and
[circular native contract](ASSEMBLY_CIRCULAR_PATH_NATIVE.md) describe the
separate underlying purposes. Advanced implementation and validation are
recorded separately; this document makes no claim of executed test coverage.

## Remaining integration

There is no new v2 saved key, direct occurrence selector, editor control,
production worker solve, authentic preview/Apply token or writeback path in
this adapter layer. Authored captures and winding have the separate core/state
representation above; their native recapture and transaction lifecycle remain
open. Calling the existing numerical solver
on detached constraints does not add those capabilities. Independent support
measurement is not a complete configured final-candidate verification pipeline.

Further work includes executing the selected-state plan, catalog-state
writeback, native capture/repair policy and winding continuity, saved selectors,
source/repair consumers, editor/history/reopen integration, BOM/export behavior
and independently solved flexible instances. Rigid variants are not flexible
assemblies. Complete assembly/demo scope remains open.

# Native references in rigid configuration states

The [closed numerical scope layer](ASSEMBLY_CONFIGURATIONS_SCOPE.md) projects
genuine current witnesses to immediate local numerical children. Their physical
root owners and original placement-chain error remain unchanged; no scoped
DTO is a material proof or a configured solve transaction.

Construction validates the complete expanded evaluation. Subsequent currentness
checks reparse all declarations through the shared core parser and compare the
same normalized source/catalog/selector/generation signature. They do not
re-expand an identical, already admitted tree. A changed declaration or invalid
input still revokes the session; no caller-object identity cache is used.

The [capture/winding state layer](ASSEMBLY_CONFIGURATIONS_STATE.md) now places
optional authored capture records in named mate overrides. The existing four-
field input remains unchanged; normalized captures are part of its complete
catalog signature. These declarations do not authenticate historical recapture.

This standalone native context follows the
[configuration evaluation core](ASSEMBLY_CONFIGURATIONS_CORE.md). It binds
current native observations to an effective selected state, with separate
purposes for frames, geometry, directions, surfaces, profiles and paths.
It does not change saved v2 syntax, the production worker/editor, scoped
solving, private Apply or flexible-instance behavior.

## Complete current input

`AssemblyConfigurationGeometrySnapshot` accepts one explicit input record:
`{ document, catalog, rootConfiguration, generation }`. All four fields are
required. The document and separate catalog are validated and detached through
the configuration core. The context never accepts an evaluation DTO as native
truth and never fabricates a base document with overridden occurrences.

Generation is a nonnegative safe integer owned by the controller. It must
advance on every context change, including leaving a state and returning to
it. It is an ephemeral lifetime label, not a saved revision or geometry proof.
A library cannot observe edits made and undone between calls without such a
controller signal. Each constructed session also has its own private lifetime;
matching public labels do not let another session accept its witnesses.

Construction, queries and assertions validate the complete current input.
Normalized source, catalog, selected root state and generation must still
match, including after native processing and before publishing output. This
input signature remains within 20 MiB. The expanded evaluation is not used as
a serialized signature or transport payload. There is no global active-session
singleton and no legacy base-document-only assertion fallback.

## Effective geometry and ownership

Private scope/part indices resolve full paths through effective occurrences.
Only active part uses contribute native prototypes, including branches which
a named state activates from a suppressed base. Hidden material remains
available. Local geometry is shared by exact part tuple; world placements,
configuration ancestry and issued proofs remain specific to each occurrence.
Existing native body, face, edge and vertex inventory caps remain in force.

`listFaces`, `listEdges` and `listVertices` return current identity metadata.
Metadata is not proof. The following explicit methods query the session's
actual current part engine; none accepts a prepared observation or provider
callback as authority.

| Query | Configured purpose |
| --- | --- |
| `resolveComponentReference` | Occurrence or scope frame; no material geometry claim. |
| `resolvePlaneReference`, `resolveVertexReference` | Current planar face/principal frame or material vertex, respectively. |
| `resolveReference`, `resolveDirectionReference` | Native plane/axis/LINE support or direction-only extraction, with distinct witness kinds. |
| `resolveCylinderSurfaceReference`, `resolveSphereSurfaceReference` | Actual surface, including radius and material sense; axis intent is separate. |
| `resolveProfileFaceSelection`, `resolveProfileAxisSelection` | Complete bounded rectangle/disk, or explicit incident rectangle boundary edge and sense. |
| `resolveLinePathSelection` | Material LINE and explicit incident start vertex. |
| `resolveArcPathSelection`, `evaluateArcPathSelection` | Material bounded arc with an incident origin, or its separate coordinate evaluation. |
| `resolvePathCurveSelection`, `evaluatePathCurveSelection` | Existing bounded-curve purpose and sense, or its separate coordinate evaluation. |

The advanced observation helper has no registry or lifetime authority. Strict
selection/band/coordinate preflight precedes the owned engine query; the class
checks the complete input again before privately issuing a frozen witness.
Arc and generic-curve origins are not interchangeable. Direction-only data
cannot grant full positional, axis-radius or surface authority. Native body,
face, edge and vertex incidence is rechecked by the existing engine queries.
Unsupported purposes reject rather than use a legacy base-state query.

Scope-relative references append to the actual scope path. A null principal
component denotes that scope's frame, including its configured placement.
The rigid owner stays the first element of the full occurrence path, or null
for the root frame. Selecting a nested scope does not grant independent motion
to a child or create another world anchor. Suppressed, missing or foreign
source paths cannot borrow a prototype available through another occurrence.

All configured witness kinds are distinct from legacy kinds. Directions,
surfaces, profile axes and path evaluations also have distinct configured kinds.
A private registry binds their object identity to one live configured session.
`assertWitness` and `assemblyConfigurationPlacementArithmetic` require the full
current input. A clone, foreign session, disposed witness or legacy proof is
not accepted. Configured proofs are not legacy snapshot or solver authority.

## Arithmetic, failure and remaining work

Placement arithmetic retains the sum of effective local translation magnitudes
and full path depth before cancellation. It does not substitute the magnitude
of the final world translation or walk base occurrences. Native topology
tolerance, rigid placement arithmetic and purpose-specific precision admission
remain separate. A small final point after large cancellation is not a
certificate of small uncertainty.

Profiles retain the existing `64 * EPSILON * (depth + 1)` composition estimate
for world position/normal and the separately extracted boundary-axis error.
Finite world uncertainty is reported without inventing a new pair-measurement
admission policy. Path observations retain the existing factor 128, requested
length/angle bands, analytic arithmetic, material frames and evaluation-specific
D1/parameter budgets. Position errors include the effective translation sum and
local/world magnitudes before any cancellation. Rigid placement does not scale
radius, length or parameter domains. Existing precision refusal remains a
native processing failure; no band is widened to admit a placement. These are
first-order float64 estimates, not certified interval arithmetic. Basic frame,
plane, point and generic support queries do not acquire a path/profile precision
certificate from this extension.

A rejected current input permanently revokes the session. Restoring its JSON
does not resurrect it. Native processing failure also revokes the context and
releases its prototypes. Invalid reference/path preflight can reject before
native processing while leaving the session usable. Disposal marks the
session dead, relinquishes ownership before cleanup, attempts every owned
engine once and is idempotent. Primary and cleanup failures remain observable.

Original cases and exact bands belong in
[provenance](PROVENANCE.md) and [actual validation](VALIDATION.md).
The context may inspect available geometry for repair even when active mate
declarations contain unavailable endpoints; it neither silently disables those
mates nor certifies their satisfaction.

The separate [effective relation layer](ASSEMBLY_CONFIGURATIONS_RELATIONS.md)
selects active/passive equations and issues private native aggregates. This
reference admission does not establish physical satisfaction or a solved state.
The separate [numerical layer](ASSEMBLY_CONFIGURATIONS_NUMERIC.md) adds detached
constraints and bounded independent hinge/profile/path support measurements.
Production variant-keyed solve/writeback, native capture transactions, saved fields,
base-occurrence selectors and source/repair/BOM/export/editor consumers still
need integration. Complete
configurations, flexible instances, external behavior parity, installed
packages, other platforms and the complete assembly/demo scope remain open.

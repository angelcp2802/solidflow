# Selected rigid configuration solve transactions

This standalone native layer connects the [state plan and closed scopes](ASSEMBLY_CONFIGURATIONS_SCOPE.md),
[capture declarations](ASSEMBLY_CONFIGURATIONS_STATE.md) and
[independent geometry gate](ASSEMBLY_CONFIGURATIONS_VERIFICATION.md). It prepares
a complete selected dependency closure, stages exact intrinsic states child
before parent and publishes an atomic candidate only after fresh native
verification of every actual placed use. Saved/editor transport remains separate.

## Preparation and exact state writeback

`prepareConfiguredAssemblySolve(input, options)` consumes the complete document,
catalog, root selector and generation. Own-data validation detaches the baseline
before native work; the original complete context is checked after each stage
and before publishing. Controllers must advance generation on every context
change, including away and back. A candidate clone alone cannot detect changes
to the original controller baseline.

Each active intrinsic state is solved once in dependency order. Its numerical
body list consists of effective direct unsuppressed children, including hidden
children with their actual fixed flags. All active equations and available
suppressed mechanical winding are resolved from a newly owned complete native
snapshot. Exact closed scopes preserve full-root material owners, references,
ancestry and original-chain uncertainty. No temporary flattened saved document,
legacy proof cast or caller-supplied native provider is accepted.

The bounded numerical solver returns every active body's proper pose and all
active/passive gear, screw and rack lifted angles. Missing, extra or duplicate
outputs, changed fixed bodies, unavailable passive references and unsuccessful
solver statuses reject preparation. State writeback changes only occurrence
poses and lifted fields; references, selectors, parameters, suppression, neutral
frames, neutral travel, phase and other capture data remain authored values.
This is not native recapture or repair.

Named writes update that exact variant. Base writes first materialize the old
inherited changed poses/captures into every named variant that lacks an explicit
replacement, including dormant/suppressed variants. Existing fields/order remain;
Core limits still apply. If isolation exceeds the 4096-override or combined byte
budget, the entire operation rejects with the input unchanged.

A shared intrinsic child state remains shared. Changing it propagates normally
to every parent that selects it; unchanged parent declaration bytes do not
promise unchanged effective child geometry. This layer does not clone definitions
or redirect selectors automatically and does not implement flexible instances.

## Numerical and mechanical boundaries

Conditioning builds numerical constraints once from genuine scoped aggregates.
It retains positional support/target/path/profile extents and uses nearby local
coordinates without inverting a composed world placement. Direction-only and
UP-only incidence omit irrelevant origins/radii. Gear phase, including active
gear phase, is angular; another positional incidence restores that owner's
positional budget. Suppressed mechanisms retain angular continuity only.
Original full-chain guards remain in the adapters and final physical checks.

Public defaults remain 1e-6 mm and 1e-8 radians. Options are strict own data;
the original solver validates its bounded policy before native allocation.
Optional tighter working length/angular targets cannot widen those bands, add
retries or replace fresh physical acceptance. No hidden convergence fraction
is selected by this transaction.

Before solving a state, its actual neutral-relative lifted coordinates must
agree with the authored anchors within the public angular band. In particular,
an earlier child rotation cannot silently rebase a parent's capture. A stale
anchor or ambiguous chart rejects; no unobserved turns or movement trajectory
are invented. Accepted solver outputs update winding while retaining complete
neutral captures. Dynamic trajectory/capture repair is a separate requirement.

## Final gate and single use

Every stage releases its snapshot before the next candidate generation is used.
Changed stages advance a safe integer generation; overflow rejects. All staged
data remains detached and private. Final verification reconstructs a fresh
complete snapshot and checks every placed relation, including reused states
at different root poses. A failure in a later state, second instance, native
query, context check or release withholds the entire preparation. Primary and
release errors are preserved together. Reports are finite and the preparation
retains the existing 20 MiB bounded-data policy.

A successful preparation is deeply frozen and registered privately. Its public
candidate and review are inspectable data; a clone or standalone report cannot
authorize Apply. `applyPreparedConfiguredAssemblySolve(current, preparation)`
consumes the original handle on every attempt, checks the exact complete
baseline and returns the privately retained complete candidate. Stale or invalid
attempts also revoke it permanently. Neither prepare nor apply mutates its input.
This API does not write a disk file or insert a legacy document-only preview.

Actual coverage belongs in [VALIDATION.md](VALIDATION.md), with original model
provenance recorded separately. The transaction uses the current all-family
adapters and final dispatch; a passing small native matrix does not establish
every relation branch or complete configurations. Parameter/part-feature
variants, native capture/repair, saved format, worker/editor/history/recovery,
dependent consumers, flexible instances and the complete assembly demo remain
required.
